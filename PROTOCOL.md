# Latch tunnel protocol (draft, protocol version 1)

Status: **normative since phase 2**; `proto/tunnel` is the executable form.

## Overview

An agent (`latchd`) opens one outbound TCP connection to a relay
(`latch-relay`) on port 7443, wrapped in TLS. Over that connection a
[yamux](https://github.com/hashicorp/yamux) session multiplexes:

- exactly one **control stream** — the first stream, opened by the agent
  immediately after the TLS handshake; carries framed JSON messages;
- any number of **data streams** — opened by the relay, one per proxied HTTP
  connection or TCP connection; carry a small JSON header followed by raw bytes.

Why not reuse frp/rathole/chisel: their wire formats are tied to their own
feature sets and config models. Latch needs policy sync and access-event
backflow, which none of them have, and the format below is small enough to
document fully.

## Transport

- TLS 1.3 (1.2 minimum), ALPN `latch/1`. The agent verifies the relay
  certificate against system roots plus an optional extra CA (dev only).
  Verification is never disabled.
- yamux with defaults except: `KeepAliveInterval` disabled (Latch uses its
  own Ping), `MaxStreamWindowSize` 1 MiB, `StreamOpenTimeout` 10s.
- If the agent does not send `Hello` within 10s of the TLS handshake, the relay
  closes the connection.

## Control stream framing

```
+-----------------+----------------------+
| length (u32 BE) | JSON payload (bytes) |
+-----------------+----------------------+
```

- `length` ≤ 1,048,576 (1 MiB). Larger frames → `ERR_FRAME_TOO_LARGE`, close.
- Payload is a JSON object (envelope):

```json
{ "t": "RouteAnnounce", "id": 42, "re": 41, "d": { ... } }
```

| Key | Meaning |
|-----|---------|
| `t` | message type (string, below) |
| `id` | sender-assigned sequence number, monotonic per direction, starts at 1 |
| `re` | optional: the `id` this message responds to |
| `d` | type-specific body |

Unknown `t` → `Error{code: ERR_UNKNOWN_TYPE}` with `re`, connection stays up.
Unknown fields inside `d` are ignored (forward compatibility).

## Messages

Direction: A = agent, R = relay.

### Hello (A → R)

```json
{ "protoMin": 1, "protoMax": 1, "agentVersion": "0.3.0", "agentId": "ag_…",
  "token": "<plain token>", "capabilities": ["tcp", "events"] }
```

- `agentId` is a stable random id generated by the agent on first run.
- Relay responds with `HelloAck` or `Error` (fatal) and closes.

### HelloAck (R → A)

```json
{ "proto": 1, "relayVersion": "0.3.0", "serverTime": "2026-11-09T10:00:00Z",
  "scope": { "hostnames": ["*.relay.example.com", "app.example.org"], "tcp": true, "tcpPortRange": [20000, 20999] },
  "baseDomain": "relay.example.com", "policyVersion": 17, "capabilities": ["tcp", "events", "geoip"] }
```

- `proto` is the highest version supported by both; if none, `Error{ERR_VERSION}`
  including `relayMin/relayMax` so each side can print "update the agent" or
  "update the relay".
- `policyVersion` is the version the relay currently holds for this token (0 = none),
  so the agent knows whether to resend `PolicySync`.
- `capabilities` with `geoip` absent tells the agent country rules will not match on this relay.

### RouteAnnounce (A → R) / RouteAck (R → A)

```json
{ "routes": [
  { "routeId": "rt_…", "kind": "http", "hostnames": ["app.relay.example.com"], "pathPrefix": "/" },
  { "routeId": "rt_…", "kind": "tcp", "tcpPort": 0 } ] }
```

```json
{ "accepted": [ { "routeId": "rt_…", "hostnames": ["app.relay.example.com"], "publicUrls": ["https://app.relay.example.com/"] },
                { "routeId": "rt_…", "tcpPort": 20004, "publicUrls": ["tcp://relay.example.com:20004"] } ],
  "rejected": [ { "routeId": "rt_…", "code": "ERR_SCOPE", "message": "hostname not in token scope" } ] }
```

- Announce is a **full set**: routes not present are withdrawn (idempotent
  resync after reconnect). `RouteWithdraw { "routeIds": ["rt_…"] }` exists for
  fast single removals and is answered with an empty `RouteAck`.
- Hostnames are lowercased by the relay. A `pathPrefix` is normalized (trailing
  slash removed, "" → "/"); the longest matching prefix wins at request time.
- TCP routes: `tcpPort: 0` lets the relay pick the lowest free port, and a route
  that reconnects gets its previous port back while it is still reserved.
- The same token may be used from several agents (`agentId`); a hostname is
  served by whichever agent announced it last. A second connection with the
  same token **and** the same `agentId` replaces the first (`Goodbye{superseded}`).
- Rejection codes: `ERR_SCOPE`, `ERR_HOSTNAME_TAKEN` (bound to another token),
  `ERR_INVALID`, `ERR_TCP_PORT_UNAVAILABLE`, `ERR_TCP_NOT_ALLOWED`.

### PolicySync (A → R) / PolicyAck (R → A)

```json
{ "version": 18, "ipPolicies": [...], "rateLimits": [...],
  "bindings": [ { "routeId": "rt_…", "ipPolicyId": "pol_…", "rateLimitIds": ["rl_…"], "headers": [...] } ] }
```

```json
{ "version": 18 }
```

- Full snapshot, monotonic `version` (the agent's config version). Relay
  persists it and applies atomically. The agent keeps `lastAcked`; if the acked
  version is behind the current one for more than 15s the relay is marked
  `out_of_sync`.
- Relay validates with `model.Validate`; invalid → `Error{ERR_INVALID, re}`
  and the previous snapshot stays in force.

### Ping / Pong (both directions)

`{ "ts": "…" }`. Each side pings every 15s; three missed pongs (45s) → the
connection is considered dead and closed. Round-trip time is reported to the UI.

### AccessEvent (R → A)

Body is the `AccessEvent` object from `docs/DATA_MODEL.md` with
`source: "relay"`. Events may be batched: `{ "events": [ … ] }` up to 500 per
frame. If the agent is slower than the event rate, the relay drops the oldest
queued events and sets `"dropped": n` on the next batch.

### Error (both directions)

```json
{ "code": "ERR_SCOPE", "message": "human readable", "fatal": false }
```

`fatal: true` means the sender will close the connection after this frame.
With `ERR_VERSION` the relay adds `"relayMin"` and `"relayMax"`.

### Goodbye (both directions)

`{ "reason": "shutdown"|"superseded"|"token_revoked"|"reload" }` — graceful
close; the receiver must not treat it as an error. `superseded` is sent to an
old session when the same token connects again (newest wins). `token_revoked`
must make the agent stop reconnecting until the user changes the token.

## Data streams

Opened by the relay for each inbound connection. First bytes on the stream:

```
+-----------------+--------------------------+
| length (u16 BE) | StreamHeader JSON        |      relay → agent
+-----------------+--------------------------+
| status (u8)     |                          |      agent → relay
+-----------------+--------------------------+
| raw bytes both ways until either side half-closes |
```

`StreamHeader`:

```json
{ "routeId": "rt_…", "kind": "http"|"tcp", "hostname": "app.relay.example.com",
  "clientIp": "203.0.113.7", "clientPort": 51234, "tls": true, "sni": "app.relay.example.com",
  "streamId": "…" }
```

`status`: `0x00` OK (agent dialed the target), `0x01` dial failed, `0x02` route
unknown/disabled, `0x03` agent busy. On non-zero status the relay serves a 502
page (HTTP) or closes (TCP) and emits an `AccessEvent` with `denyReason`.

For `http` streams the relay terminates HTTP (HTTP/1.1 and HTTP/2 on the
public side) and forwards each request as **one HTTP/1.1 request per data
stream** (`Connection: close`), with `X-Forwarded-For`, `X-Forwarded-Proto`,
`X-Forwarded-Host` and `X-Real-IP` set from the real client (any inbound
values are replaced). WebSocket upgrades are passed through: after a `101` the
stream carries raw bytes in both directions. Request and response bodies are
streamed, not buffered. The agent speaks plain HTTP/1.1 to the local target.
Stream reuse across requests is a possible v1+ optimisation.

For `tcp` streams, if the route has `proxyProtocol: true` the agent writes a
PROXY protocol v2 header to the local target before copying bytes.

## Connection string

The relay's `token create` prints one string that the agent/UI pastes:

```
latch://relay.example.com:7443/?token=<token>[&ca=<base64url(PEM)>][&name=my-vps]
```

The agent stores `host`, `port`, `token`, `caPem` as a `Relay` object and
learns `baseDomain` and scope from `HelloAck`.

## Reconnection (agent)

Exponential backoff: 1s, 2s, 4s, … capped at 60s, full jitter. Reset to 1s
after a connection has stayed up 60s. After reconnect the agent sends `Hello`,
a full `RouteAnnounce`, and `PolicySync` if `HelloAck.policyVersion` is behind.
Stop permanently on `ERR_AUTH`, `ERR_VERSION`, `token_revoked`; surface the
reason in the UI.

## Error codes

| Code | Fatal | Meaning |
|------|-------|---------|
| `ERR_AUTH` | yes | token unknown, revoked or expired |
| `ERR_VERSION` | yes | no common protocol version |
| `ERR_FRAME_TOO_LARGE` | yes | control frame > 1 MiB |
| `ERR_MALFORMED` | yes | not valid JSON / envelope |
| `ERR_TIMEOUT` | yes | no Hello within 10s / pings missed |
| `ERR_UNKNOWN_TYPE` | no | unsupported `t` |
| `ERR_INVALID` | no | body failed validation |
| `ERR_SCOPE` | no | hostname/port outside token scope |
| `ERR_HOSTNAME_TAKEN` | no | bound to another token |
| `ERR_TCP_PORT_UNAVAILABLE` | no | requested port in use / outside pool |
| `ERR_TCP_NOT_ALLOWED` | no | token scope forbids TCP |
| `ERR_RATE_LIMITED` | no | too many control messages (>50/s) |
| `ERR_SUPERSEDED` | yes | same token and agentId connected again (sent as Goodbye) |
| `ERR_TOO_MANY_SESSIONS` | yes | token already has the maximum number of agents connected |
| `ERR_INTERNAL` | varies | relay-side failure |

## Limits (relay defaults)

| Limit | Default |
|-------|---------|
| Sessions per token | 4 (older `superseded` beyond that) |
| Routes per session | 256 |
| Data streams per session | 4096 |
| Control frame size | 1 MiB |
| PolicySync snapshot size | 1 MiB |
| Control messages | 50/s per session |
| Inbound connections per client IP | 256 |
| Total inbound connections | 65,536 |
| Header read timeout / idle timeout | 10s / 120s |
